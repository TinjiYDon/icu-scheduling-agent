# 跟老师怎么说（大白话）

> 先讲清楚「我们在解决什么」，再讲「相对常见做法改了什么」，最后主动讲「哪里还糙」。  
> 详细口播步骤见 [DEMO_SCRIPT.md](DEMO_SCRIPT.md)。

## 30 秒版

老师，我们做的不是「又接了一个 OR-Tools」或者「训练了一个 PPO」。  
**分床这件事，硬约束必须能审计**，所以默认还是约束规划。  
真正多做的一步是：同样的床位和隔离/呼吸机限制下，用 **三种多目标决策方式**（加权、按优先级一层层锁、ε 底线）对照，并在 **同一批病人、同一套资源** 上和贪心比一比。  
小池子上数字经常打平——这说明在这个规模里 CP-SAT 已经够用，**我们不会硬说强化学习更强**。

## 2 分钟版（按提问答）

### 「约束是不是太简单了？」

硬约束本身就是分配问题：一个人一张床、隔离床有限、呼吸机有个上限——**故意保持可解释**。  
复杂的是：多个目标怎么权衡（先救高危还是先提高优先级总分），以及隔离/呼吸机「谁需要」目前还是规则近似，**我们文档里写明了，不装成临床金标准**。

### 「是不是拼接、没创新？」

系统当然是拼接的：数据 → 评分 → 优化 → 界面，工程都这样。  
**创新口径不放在「用了什么库」，而放在：**

1. **同一套硬约束下，换多目标决策机理**（不是只调一组权重蒙一个折中解）；  
2. **公平对照**：同一批病人、同一张病房布局，再比贪心 / 加权 / 词典序 / ε；  
3. **诚实边界**：不宣称床旁在线强化学习；小池打平就承认打平。

### 「技术栈怎么定的？有没有对比？」

- **默认 CP-SAT**：医院场景要「为什么这张床给这个人」能说清楚；没有 MIMIC 在线轨迹就不上线 RL 当主路径。  
- **PPO**：只作离线对照，有协议也不说成 online。  
- **紧迫度**：用仓内 SOFA/GBDT，不接另一个预警项目的风险分——两个课题拆开。  
- **对比实验**：同池方法 bake-off（贪心 vs 三种 CP-SAT 机理），见 `python -m application.run_method_bakeoff`。

### 「怎么证明不是空口？」

指着界面或 `STATUS` / `reports/method_bakeoff_latest.json`：  
- 三种机理都能算出可行解；  
- 词典序往往会服务更多高危——这是机制差异，不是换了个求解器 logo；  
- ε 太紧会不可行——说明边界在起作用。

### 「学术上到底创新在哪？有什么用？」

不要说发明了新算法。说三件事：

1. **可审计分床平台**：同一协议上能换紧迫度、换多目标机理、做公平对照。  
2. **预测必须接到决策（H5）**：不只比分数相关，还比「换优先级后分床名单变没变」。  
3. **滚动不是摆设（H6）**：同随机种子下，每步再优化 vs 只往空床塞人，看病情/权重均值差。

完成后的意义：别人可以在同一套 MIMIC+约束协议上继续换模型，而不是从零拼 Demo；医院侧得到的是「能说清楚的分床建议」，不是黑盒推荐。

## 一句收尾

**骨干是可审计的分床优化；加深的是多目标机理、预测→决策闭环、滚动增益，以及把局限说清楚。**
